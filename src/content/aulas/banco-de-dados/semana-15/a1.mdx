As relações entre as tabelas são estabelecidas por chaves primárias e chaves estrangeiras. Ele utiliza SQL para definir estruturas, inserir, consultar, alterar e excluir dados; também permite aplicar restrições, como `NOT NULL`, `UNIQUE` e `CHECK`, para proteger a qualidade dos dados. Em operações relacionadas, transações ajudam a manter a consistência: uma alteração é confirmada integralmente ou desfeita.\n\n### Quais são as vantagens de utilizar MySQL em comparação com um SGBD NoSQL?\n\nO MySQL é vantajoso quando a aplicação possui entidades relacionadas e regras de integridade claras, como clientes, produtos, pedidos e pagamentos. Ele oferece um esquema definido, consultas SQL com `JOIN`, chaves estrangeiras e transações. Um banco NoSQL costuma ser mais flexível para dados sem estrutura fixa e para certos cenários de escala horizontal; essa flexibilidade, porém, transfere parte da validação das relações para a aplicação. Para a TechSolutions, o MySQL reduz o risco de vendas sem cliente, itens sem produto e relatórios inconsistentes.\n\n### Em que situações um SGBD relacional se destaca para a gestão de dados de uma empresa?\n\nEle se destaca quando os dados possuem relações estáveis, quando há necessidade de consistência entre várias operações e quando a empresa precisa de relatórios que cruzam informações. Exemplos são controle de estoque e vendas, cadastro de clientes, faturamento, folha de pagamento e histórico de pedidos.
